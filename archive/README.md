# archive/ — 退役区(不是垃圾桶)

**这个目录不进索引、不进图谱、不被 lint 检查、不参与 GC 的任何整理。** 移进来的东西从此不占你任何注意力,但内容还在、git 历史还在、随时能移回去。

## 为什么要有它

2026-08-02 认定的结构问题:这个库**只有入口没有出口**。规则写着「notes 只做去重合并,不自动降级、不自动删除,删除权只在用户」——本意是保护,实际效果是**唯一的出口需要你亲自下删除的决心**,所以什么都出不去,只能一直涨。

归档补的就是这一层:

> **你需要的不是删除的决心,是一个不用下决心的动作。**

「要不要永久删掉这条」是不可逆的、要想很久的决定;「先挪走看看」是可逆的、几秒钟的动作。后者才做得动。

## 什么该进来

- 📖 参考层里已经过时、或换了更好来源的
- 同族合并之后被吸收掉的旧笔记(主笔记里已经完整包含它的内容)
- 向上蒸发之后的笔记:判断已经完整长进某个概念页的定义里,笔记本身成了空壳
- 你自己看着不想再在库里看到、但也不想真删的任何东西

## 什么不该进来

- 🧠 核心层。那是"你当时怎么想"的记录,过时了也仍然是记录——过时本身就是信息。
- 还有入链的笔记。先处理链接(见下),再移。

## 归档动作(三步,顺序不能反)

1. **先断链**:全库搜这篇的路径,把指向它的 `[[wikilink]]` 改成纯文本路径,并在那句话里注明「已归档」。**跳过这步会让 lint 报断链错误、CI 直接红灯**——这是故意的,机器帮你守住顺序。
2. `git mv notes/xxx/yyy.md archive/`,frontmatter 加一行 `archived: YYYY-MM-DD` 和一行 `archived-reason:`(一句话,为什么退役)。
3. 重跑 `build_memory_index.py`(它只扫 profile/concepts/notes,归档的自动从索引消失)+ `lint_memory.py` 确认 0 错。

## 找回来

`git mv archive/yyy.md notes/对应分类/`,把第 1 步的链接改回去。没有任何东西丢失。

## 顺带一句:git 本身就是回收站

真删掉的文件也能找回来:`git log --diff-filter=D --oneline -- '*关键词*'` 找到删除那次提交,`git show <commit>^:<路径>` 就是删之前的完整内容。这个库从建立起没丢过任何历史。

**知道这一点本身就是机制的一部分**——不敢删,有一半是因为以为删了就没了。它没有。
