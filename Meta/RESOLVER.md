# RESOLVER — 新内容该放哪

按顺序判断,命中第一条就停,不用继续往下看:

1. **用户自己在 Obsidian 手写、推送到了 GitHub,没有触发词** → `Notes/`(GC 或用户主动触发「帮我梳理一下 notes」时补齐分类、frontmatter、双链)
2. **用户说了**「记下来」「存一下」「收藏这条」「写进记忆库」「remember this」等触发词 → **先判断内容性质,不是无脑塞进 Notes/**:
   - 文章、知识点、用户自己的想法/创作/经历 → `Notes/`(提炼后写入,完整流程见下方「写 notes 的执行流程」)
   - 关于用户本人的稳定信息或偏好 → `Profile/` 对应主题页(不进 Notes/)
   - 对 AI 未来工作方式的约束或决定 → 直接写进 `CLAUDE.md` 对应规则(不单开记忆文件)
   - 一条内容同时沾两类(比如"以后笔记都用 X 格式"既是知识又是约束)→ 知识部分写 `Notes/`,约束部分写进 `CLAUDE.md` 规则
3. **观察到用户本人的稳定特质**(行为准则、偏好、兴趣——用户明确表达过,或重复出现 ≥2 次)→ 更新 `Profile/` 对应主题页,**只写结论本身,不附依据、日期、出处**(不需要触发词,主动写,写完告知;见 CLAUDE.md「Profile/」一节)
4. 都不是 → **什么都不写**

**不要写**:代码里 grep 就能查到的事实、一次性任务细节、没有复用价值的流水账、记忆库自身的运营流水——记忆库只记用户(profile)和用户的知识(notes + concepts),不记 AI 自己的操作流水或抽象判断。对 AI 未来工作方式的硬约束直接写进 `CLAUDE.md` 规则,不单开记忆文件。

**只有写 Notes/ 时**才按 `Meta/CONCEPTS.md` 的规则在正文概念出现处挂 `[[Concepts/xxx]]` 链接(概念页不存在也照写,幽灵节点零成本);**笔记之间是否直接互链看情况**——默认优先走概念枢纽保持图谱清爽,但出处/背景引用、强绑定的一对、或走概念反而绕远时,直接挂 note→note 双链也可以,哪种贴合内容用哪种。`Concepts/` 不是录入目的地——概念页只在被第二篇笔记命中时才建。**Profile/ 不挂概念链、不做双链进图谱**,引用其他记忆用纯文本路径;图谱只属于用户的知识(notes + concepts)。

写完之后:重跑 `python3 Meta/scripts/build_memory_index.py` 更新索引;最后按 CLAUDE.md「写入必须告知」的格式告诉用户。

## 写 notes 的执行流程

上面判断出「该写 Notes/」之后才走这一节:

1. 提炼成一条笔记(不是全文粘贴)。**提炼 = 选择性,这是设计不是偷懒**,但选择必须守两条边界:
   - **用户自己说的话不做取舍**:提问、反问、自述、当场的判断和纠正——一律进库,哪怕当时看不出价值。今天觉得没用的一句自述,往往正是 profile 里某条模式的一个佐证。
   - **可以压缩的只有 AI 那一半**:论证过程、举例、铺陈。**而且 AI 那一半基本不该以"AI 说过什么"的形式留在笔记里**——留结论和机制,不留"AI 当时提了 X、被驳回了 Y、这是第几次命中",判据见 CLAUDE.md「只记内容,不记这个文件怎么长出来的」那条。压缩不等于丢弃——**判断"这段不用记"时,理由要写进 `Sources/` 映射表那一行**(例:"查一次就知道的操作性事实""一次性反馈,无复用价值"),不能默默跳过。
   - **提炼出来的必须是一篇能独立读完的文章,不是对来源的批注**——不许出现"原文""这段对话"(见 CLAUDE.md「只记内容」),也不许让小标题抄来源的目录(见 CLAUDE.md「Notes/」节「骨架从主张长出来」那条)。
   - 要防的不是选择本身,是**选择没有留下痕迹**——漏掉的和主动不记的混成一团,事后无从分辨。
2. frontmatter 用 `type: note`,加一行 `source:`、一行 `tier:`(三选一,见下)、**一行 `created: YYYY-MM-DD`**;可自由建子文件夹分类,索引脚本递归收录。**文件夹按需再建,不按数量凑**(lint 不再有「超过 12 篇就该拆」的机器警告)——判据是翻起来费不费劲、同一文件夹里是不是已经长出了明显的次主题,不是数够了没有。真要拆就**往深里拆**:在那个文件夹**里面**开子文件夹(`Notes/个人/动机与改变/成瘾/`),不要在 `Notes/` 下平铺出新顶层。顶层数量仍然锁在 10 个以内,超了 lint 会警告——不封数量的话,按 9 篇/周一年就是 40 个顶层文件夹。**日记不在 Notes/ 里**,见 `Diary/README.md`
3. **用户发来的是对话导出文件时(多轮 md/txt 导出),必须同时在 `Sources/` 建一份映射表**——这不是可选的后续动作,和「重跑索引」同级,漏了就是流程没走完。格式见 `Sources/README.md`:一轮一行,记去向(✅ 进了哪篇 / ⚠️ 半记 / ❌ 没记,没记的要写为什么)。**原文本身也要拷进 `Sources/raw/`(同名)**——用户可能随手删掉自己那份,而上传目录会话一结束就清空;没有原文,映射表里「第 N 轮漏了」这句永远无法复核。**原样拷贝,不脱敏、不删行**(脱敏过的原文失去复核价值,见 `Sources/README.md`)。**告知用户时把它一起说出来。**
   > 为什么强制:一份几十轮的导出整块漏掉几段,不做对照表就没有任何机制能发现。对照表是防这个的,而一条"什么时候必须建"的规则是防对照表本身被忘掉——否则整道防线依赖"有人记得"。
4. **推之前从头读一遍,只找一样东西:哪一句在讲这个文件怎么长出来的。** 「同一场对话」「工作台问题 N」「原文说」「补录」「先前记成」「2026-XX-XX 用户确认」——挑出来改成直接陈述,判断和原话一个字都不删。**这一步是单独的工序,不是"顺手注意一下"**:写的时候来源在上下文里、读的时候不在,这条不对称让边写边自查必然失效,只有写完换个身份重读才抓得住。`lint_memory.py` 只兜得住词表里那几种说法,而词表是从已发现的病例归纳的,必然漏。
5. 写入本仓库、重跑索引、提交推送到 main。**"记下来"永远指写进这个 git 仓库**,不是会话内的短期记忆或任何 AI 产品自带的记忆功能
6. 当前会话没有本仓库时先获取(远程会话用 add_repo 添加 jadecoltrane/memory;本地会话直接操作用户磁盘上的 clone),实在无法访问时把写好的内容整段输出给用户手动保存

### 分层:tier(决定这条以后能不能淡出)

索引按这三层分组展示,🧠 在最上、📖 垫底,想只看要紧的就从上往下读、把最后一段折叠掉。

- **`tier: 核心`** 🧠 —— 用户自己的判断、立场、经历、反复回来的问题。**永不自动降级、永不建议删除**,过时了也是"这个人当时怎么想"的记录
- **`tier: 方法`** 🔧 —— 可执行的做法、清单、操作流程。会被更好的做法替代,替代时按 GC 的去重合并处理
- **`tier: 参考`** 📖 —— 外部知识、事实、别人的理论、一次性查阅材料。**这一层允许淡出**——过时了换一份就行,不需要用户下"删除"的决心;GC 里唯一可以主动列进摘要建议清理的就是它

### created 必填,不是可选装饰

`Home.md` 那个「本周新增」计数器**只认 frontmatter 的 `created`,而且故意不退回文件时间戳**(一次 clone 或 checkout 会把 ctime 整批刷成"刚才",拿它兜底会把老笔记全算成本周新增)。**所以漏写 created = 这篇笔记在统计里永远不存在**——不报错、不断链、lint 也不管,唯一的症状是数字对不上,而没人会为了一个偏小的数字去查。

这条曾经漏在规则之外:CLAUDE.md「只记内容」那条把 `created` 列为机器要读的字段,但本文件的执行流程只要求 `type`/`source`/`tier`,于是照着流程写的笔记系统性地缺这一行。

**唯一例外**:`Diary/`、`Works/` 不需要(它们不进这个统计,也不要 frontmatter)。

拿不准写哪层时看一个问题:**这条如果三年后被证伪,损失的是"一个事实"还是"我的一段想法"?** 前者是参考,后者是核心。

### expires(只有 📖 参考层要填)

参考层的东西会过时,但没人会主动想起来去查。写这篇时顺手估一个"大概多久之后该重看一眼",填 `expires: YYYY-MM-DD`,`gc_report.py` 到期会提醒,用户回一个字就行。**这不是删除倒计时**,到期只是问一句"还要吗"——要就往后推。

粗略档位:AI/技术类半年,产品/店铺/方案类一年,心理学理论/定义性知识两年。🧠 核心和 🔧 方法层不填这个字段。

### 入库那一刻先分三类:永恒 / 带日期 / 指针

`expires` 是**两年后提醒一次**,入库当下不做任何判断——所以会过时的东西能安安静静躺两年。这一条补的是入库那一刻:**每条外部事实,写下来之前先归到三类里的一类。**

- **永恒**:机制、原理、定义、别人的框架。会被推翻但不会"过期"(双加工理论、社会渗透理论、BM25 怎么算分)。正常写,不用特殊处理。
- **带日期**:当时为真、以后会变的具体数值和状态(某模型的上下文长度、某产品的定价、某个项目现在进行到哪)。**必须在那句话里写清是什么时候的**(「截至 X 年 X 月」),不写就是在制造一条看不出已经过期的记忆。
- **指针**:变化快、而且随时能查到原处的东西(API 文档、价格页、排行榜)。**只留链接和一句话结论,不要把内容抄进来**。抄进来的那一刻它就开始烂,而且烂得没有声音。

判据一句话:**这条信息半年后如果变了,读的人看得出来它变了吗?** 看不出来,就说明它该是"带日期"或"指针",不该原样抄成一条笔记。

这三类和 `tier` 是两个维度,不冲突:tier 管"这条以后能不能淡出",这三类管"这条会不会烂在库里"。

### draft / published —— 一篇笔记走向 `Works/` 的两段路

一条笔记有三种状态,`Meta/scripts/publish_candidates.py` 把它们分开,不用人记:

| 状态 | 怎么标 | 脚本怎么报 |
| --- | --- | --- |
| **未动** | 什么都不用做 | 列进候选(核心层 + 带冲突) |
| **在写** | `Works/` 里的稿子正文写一行来源路径,例 `Notes/思考/xxx.md` | 挪进「✍️ 在写」,不再当候选提醒 |
| **已发** | **在稿子里**写一行 `published: 渠道 日期`(例 `published: 小红书 2026-08-10`) | 脚本回写进那篇稿子所有来源笔记的 frontmatter,之后移出候选池 |

- **「在写」靠扫路径认出来**:脚本读 `Works/**/*.md`,把正文里出现的 `Notes/xxx.md`、`Concepts/xxx.md` 当成这篇稿子的来源。`Works/` 引用笔记本来就用纯文本路径(见 `Works/README.md`),所以不需要为此新增任何格式。
- **也可以从笔记那侧标**:笔记 frontmatter 写 `draft: Works/xxx.md`,脚本两边都认,合并成同一条去向。
- **一稿多源是常态**:一篇长文引七八条笔记,那七八条会一起从候选池挪走。
- **没标来源的稿子会被单独列出来**(`📄 Works/ 里没标来源笔记的稿子`)——不是错,是让"这篇是凭空写的还是从哪条笔记长出来的"保持可见。
- **`published` 不用手填进笔记**:发出去之后在 `Works/` 那篇稿子里写一行 `published: 渠道 日期`(写 `已发:` 也认),`publish_candidates.py --sync` 会把它写进这篇稿子每一条来源笔记的 frontmatter。不带 `--sync` 只报告待写入的有哪些,不改文件。笔记那侧已经有 `published` 就跳过,不覆盖。
- **一篇稿子引了七条笔记,七条一起标已发**——这正是想要的:那七条都已经出去过了。个别不想标的,事后自己删掉那行。
- 用户口头说「这篇发了」时,AI 直接把 `published:` 加上,不用等用户自己动手。
- `published` 一填就永久留着,不用清。

### 先判断是否"可查证"

- **事实性/可查证**(数据、健康、历史、科学结论、他人转述的客观陈述等):走 verified + 复核流程
- **主观性/不可查证**(个人想法、感受、散文、创作、经历叙述、审美偏好):frontmatter 加 `checkable: false`,**不设 verified 字段,永远不进复核队列**——这类内容没有"对不对",原样留存即可

**verified 标记**(仅 `checkable` 内容需要):内容来自用户自己亲历/验证过的判断 → `verified: true`;转述自其他 AI、网络、他人、未经交叉核实 → `verified: false`。拿不准时默认 `false`。

### 图片(截图等)

用户发图片并说「记下来」时:

1. 原图保存到 `Notes/assets/YYYY-MM-DD-简短描述.png`(或原格式,不要转码压缩)
2. 对应 note 里用 `![说明](assets/文件名)` 嵌入原图,**并且必须额外写一段文字提炼**——图片本身无法被索引和 grep,未来 AI 靠这段文字才知道这条记忆在讲什么
3. 单张截图正常几百 KB 到几 MB,GitHub 单文件上限 100MB,无需顾虑;但不要把长视频或高清大图仓库当网盘用
