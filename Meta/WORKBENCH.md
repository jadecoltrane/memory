# WORKBENCH — 工作台(每日生成)规范

只在处理"工作台"相关任务时读这份文件(用户点名提到工作台、要改 `Home.md`、或跑 `daily-workbench.yml`/`weekly-gc.yml` 里涉及工作台的步骤)——**根规则文件不再内联这节内容,平时聊天不需要加载这份文件**。

根目录 `Home.md` 是记忆库的出口:让旧记忆主动找上门,核心是提取练习而不是重读。页面固定为 **☀️ 每日回路**(`##` 标题,AI 板块)。每天由定时任务重新生成 AI 板块,其余部分(`##` 标题、所有 dataviewjs 区块——横幅、信息条、今日内容折叠壳、胶囊标签栏(笔记/概念/本周新增/最近编辑四颗点开在页面内展开面板,双链胶囊直接跳原生图谱不展开面板,➕ 新建在最右)、🎲 随机重逢卡、✅ 每日习惯卡)是固定结构或实时渲染,**生成时原样保留,永远不要改动**。

**✅ 每日习惯卡**读写 `Profile/习惯打卡.md`:「习惯」区是清单,「记录」区每天一行 `- 日期 | 勾掉的习惯`。卡片上的 🔥 是现算的连续天数(从今天往回数,断一天即停;当天还没勾不算断)。这张卡是用户自己的打卡数据,**日更不要碰这个文件、也不要替用户补勾或清空**;要改清单只改「习惯」区。

**笔记面板**点分类卡打开的是 `Meta/笔记数据库.base`(Obsidian 原生 Bases,每次点开笔记面板都会重新生成,视图按 `Notes/` 当前的子文件夹实时同步)——这是生成产物,不是用户笔记,不要手动编辑,也不要把它当成笔记内容去索引/复核。格式保持现有 callout 语法(`[!today]` `[!draw]` `[!seed]` `[!ask]` `[!note]` `[!write]` `[!clash]`);frontmatter 保留 `cssclasses: workbench`,但每次**必须把 `generated:` 更新为当天日期**——横幅心跳报警靠它判断每日任务是否还活着(超 48 小时未更新显红),这是"系统静默挂掉"唯一的可见信号。云端日更由 workflow 前置 sed 步骤机械写入,AI 原样保留即可;只有人工/本地更新工作台时才需要手动改这个字段。


**视觉基调**:由横幅画作在客户端用 canvas 取主色调自动算出(色相分桶投票,不用平均色——平均会把所有颜色互相抵消成灰)、写进 CSS 变量 `--wb-accent`,CSS 里再用 OKLCH 相对颜色语法派生锁定亮度的文字色/柔光底。**卡片不做入场渐显**:`wb-rise-in` 那套 keyframes、逐块延迟阶梯、滚动驱动的 `animation-timeline: view()` 已整体从 `workbench.css` 删除,别再加回来——悬停/按下的 transition 不在此列,保留。

**🖼 每日画作**(横幅背景):每天生成时用执行器可用的网页搜索工具挑一幅著名画作(Claude 自动化使用 WebSearch/WebFetch),优先 Wikimedia Commons 上 `upload.wikimedia.org` 开头的直链图片(几百 KB 到 2MB 的中等分辨率版本,不要几十 MB 的原图),写入 frontmatter 三个字段:`painting-url`、`painting-title`(画名·作者)、`painting-intro`(一句话简介)。**链接必须是当次搜索/抓取真实确认可访问的**。选画不许与近半年重复(查重命令:`git log --since='180 days ago' --format= -p -- Home.md | grep '^+painting-title'`,输出仅每天一行画名,省 token 且永久封顶;不要跑裸的 `git log -p`),并在时代/地域/风格上轮换,不要连续几天同一风格。**第一个候选验证失败(链接打不开、不是直链等)不算完事,换一幅候选继续试,最多尝试 3 幅**;3 幅都验证失败才保留前一天的值,不编造 URL——保留是最后的兜底,不是遇到第一次失败就退回的默认选项。

每日生成四个板块:

> ⚠️ **四个日更块是平铺的顶层 callout**,`Home.md` 里既没有 `## ☀️ 每日回路` 标题也没有 `[!today]` 折叠壳。**按平铺的顶层 callout 生成**,别为了让文件符合上面那句描述去加壳;规范和现实冲突时以现实为准(CLAUDE.md 反信息茧房第 1 条)。

- **🎴 今日抽卡**:从 `Notes/` 挑"最久没被抽过"的——**优先看各篇 frontmatter 的 `last-surfaced:`,没有这个字段的排最前**(翻 git log 只作兜底,贵)。抽中之后**必须给被抽中的每篇写上 `last-surfaced: 今天日期`**(有就覆盖),这一行让下次挑选和 `gc_report.py` 都变成免费的。出 1-3 道回忆提示。**格式只有标题+问题列表,不加任何引导语**——不要加"先别点开"、"想不起来再点进去"之类的提示句,直接呈现问题本身。
- **🌱 今日延伸**:挑一个概念页(优先最近被链到的、或延伸区还空着的),补一条外部知识,标 [事实]/[推论]/[观点]、注明未联网核查;同步写进该概念页延伸区。**引用某篇笔记的录入时间时用实际日期。
- **❓ 今天的问题**:每天出**两道**独立问题(问题1、问题2),优先从概念页开放问题、或笔记间张力里出;**问题形式不限**——可以是指向用户自身经验的具体提问,也可以是纯开放式的观点/推演题,不强制绑定个人经历,两道题尽量来自不同概念/笔记,避免同质。**措辞用简单直白的口语**:不要堆砌概念术语、不要写长复杂句——得先在脑子里查一遍这些词/句子结构什么意思才能读懂问题本身,这已经构成理解障碍而不是引出思考;需要的背景直接用大白话嵌进问题正文里讲清楚,不要求读题的人自己代入行话或去翻概念页。**页面顺序固定为两张问题卡紧挨着,不能打乱或在中间插别的块**——靠这个顺序 + 页面级卡片网格的 flex 换行,两张问题卡自动横排成一行:
  1. `[!ask]` 问题1 → `[!ask]` 问题2:标题写 `❓ 问题1`/`❓ 问题2`,内容第一段是问题正文;**紧接着先嵌套** `[!write]` 子 callout(嵌套写法:问题的引用块内再用 `> >` 包一层),标题固定 `✍️ 你的回答`,内容留 2 行空的嵌套引用行(单独一个 `> >`)给用户手写,不预设任何文字
  2. **再嵌套**一个折叠的 `[!note]-` 子 callout(同样 `> >` 写法),标题固定 `💬 我的看法`,内容是 AI 对应问题的倾向性判断,标注 [推论]/[观点],不假装客观,折叠是 honor system,展开与否交给用户自觉。**回答区排在"我的看法"前面**——写自己的答案时不能先看到 AI 的看法,避免被提前锚定,所以顺序固定"问题正文 → 你的回答 → 我的看法(折叠)",不能颠倒。**回答区并进对应问题卡内部,不是独立顶层卡片**(独立空卡看着像 UI 没加载完,跟问题的配对关系也读不出来),"输入井"凹陷样式由 CSS 管,生成时只管结构

- **📔 今日日记**:固定排在页面**最后**,在两张问题卡之后。结构就是一个顶层 `[!write] 📔 今日日记`(标题里的 📔 不能丢——`Home.md` 挂日记按钮的 dataviewjs 靠它认这个井,认不到就静默不挂、不报错),内容留两行空的引用行给用户手写,**markdown 里不预设任何文字、不出题**——它是空白页,不是问答。**井里不要加提示语**——写进井里的任何文字都会被下面归档流程第 2 条当成用户手写的日记原文抄进 `Diary/`,每天抄一遍。归档流程:
  1. **生成新一期之前先读上一版这个井**。有内容 → 追加进 `Diary/<年>/<年>-<月>.md`,段标题用 `## <上一版 frontmatter 的 generated: 日期>`——**是上一版的日期,不是今天**,那才是这篇日记写的那天。年份文件夹和月份文件不存在就建
  2. **原文照抄,不改写、不提炼、不总结、不修错字**。日记的价值在原样,提炼是 `Notes/` 的事
  3. 新一期的井重新留空。空井不归档,月份文件里不留空段
  4. 归档了就在当次 commit message 里写明归档了哪一天(写入必须告知,日记也不例外)
  5. 日记读到值得沉淀的东西,按 `Meta/RESOLVER.md` 正常流程写 `Notes/` 或 `Profile/`,**原文留在日记里不动**;`Diary/` 本身永远不被 GC 碰(见 `Meta/GC.md` 管辖范围那段)

  **归档前先看一眼内容和 `generated:` 日期对不对得上**,可疑就去 `git log -p -- Home.md` 翻上一两期核实真实日期,**宁可归档进错的那天不如先不归档**——日记记错日期比晚一天入库严重得多。

**生成前必做**:读上一版每张问题卡里嵌套 `[!write]` 的回答。**按文档顺序对应**:第一个 `[!write]` 是问题1的回答,第二个是问题2的回答(嵌在问题卡内部,顺序对应关系不变)。**分别独立判断**,哪个 `[!write]` 里有内容就处理哪道:

1. **记录(只在值得时,取代旧的"无条件归档")**:判断这条回答值不值得留存——**只有当回答里有值得记住的判断/经历/观点/新张力**,才提炼进相关 `Notes/` 笔记或概念页(按 `Meta/RESOLVER.md` 的写 notes 流程 + `Meta/CONCEPTS.md` 的概念规则;写 notes 时用 `type: note`、加 `source: 工作台问答`、按 checkable 规则判断、挂概念双链)。**没必要记的就不记,也不再往 `Notes/问答/` 建按月归档文件**——旧回答本就留在 git 历史里,不会凭空消失
2. **碰撞(有回答时必须生成)**:在新工作台 🎴 抽卡**之前**,每道被回答的问题各插入一个 `[!clash]` callout(**默认展开,不要加折叠符 `-`**;两道都答了就两个,按问题1/2顺序排),标题 `🥊 碰撞 · 问题1 回顾`/`🥊 碰撞 · 问题2 回顾`。**固定这个四段嵌套结构(CSS 按这个结构做视觉分层,顺序和层级不能变)**:
   1. 顶层第一段是**斜体**的问题一句话概括(不加"问题:"标签,直接斜体正文)
   2. 嵌套 `> > [!write] 🗣️ 你的回答`(原文摘要,不改意,不折叠)
   3. 嵌套 `> > [!note] 💭 我的看法(上期)`(从上期折叠 callout 里搬来,完整展示,不折叠)
   4. 顶层最后一段是 `**碰撞：**` 开头的正文段——这段是全卡视觉最重的部分(CSS 给了强调色左边框+加粗),必须落在真正的分析上:指出两者的核心分歧在哪、谁的角度更贴近实际经验、哪里 AI 在偷懒或过度抽象、哪里用户可能在自我美化或回避——**不要和稀泥,不要都说有道理,要有立场**
   顶层内容只能是「第一段斜体问题」+「两个嵌套 callout」+「最后一段碰撞正文」这四块,中间不要插其他段落,CSS 的 `:first-of-type`/`:last-of-type` 选择器依赖这个顺序

   ⚠️ **第 4 段碰撞正文还有下面几条硬要求,和"要有立场"同等级,不是可选加分项**。要防的是:碰撞的落点全落在"这印证了你库里已经有的某条模式"上,整段论据一条都出不了本库——那正是 CLAUDE.md 反信息茧房第 3 条的不合格判据。
   - **每段碰撞至少要有一块本库里查不到的东西**:成熟外部知识(心理学/社科/医学里具体的研究、机制、反例、量级数字),或者对"提问方和回答方共同默认的那个前提"的拆解。二选一,不能两样都没有。
   - **禁止把「这接上了你早就报过的模式 X」当成落点**。把一个行为归到已有的画像标签上是换标签,不是解释;而且这是记忆库最容易自我强化的方向——库里存着的模式,重新认出来一次就显得很有洞察,实际信息量为零。可以提这个模式,但必须再往后走一步:外部知识对这类行为怎么说、有没有更好的解释、这个标签在哪里是错的。
   - **优先去查两边共享的那个隐含前提**。碰撞最值钱的时候不是判谁对,是发现两边默认了同一个错的动作或定义(比如两边都默认"关系往深走 = 打听对方私事",而社会渗透理论说机制是自我披露的相互升级,"礼貌"挡住的是一个本来就不该做的动作——这一步把整场"哪条原因才是真的"之争直接架空)。
   - 外部知识照 CLAUDE.md 标 [事实]/[推论];**执行器有联网工具时必须当场核查作者、年份、期刊,不要凭印象写引用**,核查过就在标注里写明"已联网核查"。
   - **自检**:写完把这段论据逐条过一遍,若全部都能在本库 grep 到,这段不合格,重写。

   同一条要求也适用于问题卡里折叠的 `💬 我的看法`——它是下一期碰撞的输入,如果它本身只是库内推断,下一期就没有外部支点可用,碰撞只能回到"你说的和你以前说的一样"。
