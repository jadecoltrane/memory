# WORKBENCH — 工作台(每日生成)规范

只在处理"工作台"相关任务时读这份文件(用户点名提到工作台、要改 `Home.md`、或跑 `daily-workbench.yml`/`weekly-gc.yml` 里涉及工作台的步骤)——**根规则文件不再内联这节内容,平时聊天不需要加载这份文件**。

根目录 `Home.md` 是记忆库的出口:让旧记忆主动找上门,核心是提取练习而不是重读。页面固定为 **☀️ 每日回路**(`##` 标题,AI 板块)。每天由定时任务重新生成 AI 板块,其余部分(`##` 标题、所有 dataviewjs 区块——横幅、信息条、今日内容折叠壳、胶囊标签栏(六颗,宽度跟字走、自动折行:笔记/概念/今日编辑/最新笔记/最近浏览五颗点开在页面内展开面板,双链胶囊直接跳原生图谱不展开面板;最近浏览读 Obsidian 自带的最近打开列表,固定 8 条、不带「展开全部」)、🎲 随机重逢卡、✅ 每日习惯卡)是固定结构或实时渲染,**生成时原样保留,永远不要改动**。

**✅ 每日习惯卡**读写 `Profile/习惯打卡.md`:「习惯」区是清单,「记录」区每天一行 `- 日期 | 勾掉的习惯`。卡片上的 🔥 是现算的连续天数(从今天往回数,断一天即停;当天还没勾不算断)。这张卡是用户自己的打卡数据,**日更不要碰这个文件、也不要替用户补勾或清空**;要改清单只改「习惯」区。

**笔记面板**点分类卡打开的是 `Meta/笔记数据库.base`(Obsidian 原生 Bases,每次点开笔记面板都会重新生成,视图按 `Notes/` 当前的子文件夹实时同步)——这是生成产物,不是用户笔记,不要手动编辑,也不要把它当成笔记内容去索引/复核。格式保持现有 callout 语法(`[!today]` `[!draw]` `[!seed]` `[!read]` `[!feed]` `[!note]` `[!write]`);frontmatter 保留 `cssclasses: workbench`,但每次**必须把 `generated:` 更新为当天日期**——横幅心跳报警靠它判断每日任务是否还活着(超 48 小时未更新显红),这是"系统静默挂掉"唯一的可见信号。云端日更由 workflow 前置 sed 步骤机械写入,AI 原样保留即可;只有人工/本地更新工作台时才需要手动改这个字段。


**📱 小组件速览段**:frontmatter 之后、第一个 dataviewjs 之前有**固定五行**纯文本(抽卡笔记名+日期 / 抽卡第一问 / 今日一读的体裁+标题 / 两行零宽空格占位)。它只服务 iOS 主屏的「查看笔记」小组件——那个小组件跑在系统扩展进程里,不加载插件也不套主题 CSS,只把笔记原始文本切一段显示,所以文件开头是什么它就念什么。**末两行占位不是凑数**:小组件有多少空间就往下念多少,速览不把那一屏占满,剩下的空间它就接着念 ```dataviewjs。页面里由 `workbench.css` 整段藏掉——阅读视图靠段内的 `#工作台` 标签认,实时预览按行切 DOM、只能从带标签那行往下数四级,所以**行数(脚本里的 `WIDGET_LINES`)和 CSS 里的 `+ .cm-line` 链长是死绑的,改一个必须改另一个**,标签也固定在第一行(兄弟选择器只能往后数)。**`Home.md` 里不许再出现第二个标签**(实时预览那条只认得出「这行有标签」,认不出是哪个;脚本的 `stray_tags` 会拦,拦住就是当天日更失败)。**由 `Meta/scripts/update_widget_block.py` 机械重写**(日更 workflow 在生成之后、体检之前跑;整段被删了会自动补回),**AI 生成工作台时原样保留、不要手改**。第一行带日期,是「日更还活着」在手机上唯一看得见的信号——小组件停在旧日期,说明云端没跑或 Obsidian Git 没拉下来。

**视觉基调**:由横幅画作在客户端用 canvas 取主色调自动算出(色相分桶投票,不用平均色——平均会把所有颜色互相抵消成灰)、写进 CSS 变量 `--wb-accent`,CSS 里再用 OKLCH 相对颜色语法派生锁定亮度的文字色/柔光底。**卡片不做入场渐显**:`wb-rise-in` 那套 keyframes、逐块延迟阶梯、滚动驱动的 `animation-timeline: view()` 已整体从 `workbench.css` 删除,别再加回来——悬停/按下的 transition 不在此列,保留。

**🖼 每日画作**(横幅背景):**由 `Meta/scripts/pick_painting.py` 在生成之前纯脚本挑好,AI 不参与、不要动这三个 frontmatter 字段**(`painting-url`/`painting-title`/`painting-intro`)。候选池 `Meta/画作池.md` 由 `build_painting_pool.py` 从 Wikidata 拉,知名度按 sitelinks 排;流派和国别各有冷却期,所以"时代/地域/风格轮换"是机械执行的,不再写在 prompt 里。查重仍由 `painting_log.py --check/--record` 拦在提交之前。

每日生成五个板块:

> ⚠️ **五个日更块都是平铺的顶层 callout**(📰 简讯夹在两个 dataviewjs 之间,其余四个在页面末尾),`Home.md` 里既没有 `## ☀️ 每日回路` 标题也没有 `[!today]` 折叠壳。**按平铺的顶层 callout 生成**,别为了让文件符合上面那句描述去加壳;规范和现实冲突时以现实为准(CLAUDE.md 反信息茧房第 1 条)。

- **📰 简讯**:用户做新能源车企座舱 UX(上海、出海车型),要每天扫一眼世界上发生了什么。**位置固定在 ✅ 每日习惯那个 dataviewjs 块正上方**(紧贴,中间只许空行)——这是唯一一块不在页面末尾的日更块,重写页面时别把它挪下去和其他 callout 放一起。整块每天覆盖、不归档;用户说「记下来」才进 `Notes/`。
  - **选什么**:3–5 条,过去 48 小时内的。**汽车/新能源只占 1 条**(中国车企动态、政策法规、电池与智驾、出海和关税、座舱交互相关的优先),**其余全是国家大事和重大新闻**:国内外时事政治、国际冲突、宏观经济/金融市场、科技大事,按影响面挑,不按好不好玩挑,也不按和汽车沾不沾边挑。用户明确说过汽车别多,一条就够——汽车新闻再多也只挑最重要的那一条。同一件事只写一条;昨天写过的事没有实质新进展不重写。政治类只陈述事实,不站队
  - **怎么找**:**只从 `.news-candidates.md` 里挑**。它是日更前置步骤 `Meta/scripts/fetch_news.py` 用纯脚本拉的固定源 RSS(国际/国内/财经/科技/汽车分组,近 48 小时,每条带时间、来源、标题、链接、摘要;源列表在脚本的 `FEEDS` 里,改视野就改那里)。**不要再 WebSearch/WebFetch 满网找新闻**——原来那样一次几十次抓取、上万 token,搜索对当天新闻还很弱。照摘要写;摘要太薄、写不出「发生了什么」才打开那一篇,一天最多 2 篇。摘要里没有的细节不要补。**照摘要写是默认,正文里不要写「我只看了摘要」之类的声明**(用户明确说过不用说)
  - **链接原样用清单里的**,`check_news_brief.py` 逐条对账,清单外的链接直接拦。清单不存在或没有够格的就少写,一条都没有就整块只写一行 `今日未抓到可靠新闻。`。本地手动更新时先跑 `python3 Meta/scripts/fetch_news.py`
  - **版式**(和用户给的参考截图一致,`check_news_brief.py` 按这个查,CSS 也按这个认):
    ```
    > [!feed] 📰 简讯
    > **原文标题(照抄来源标题;来源没有标题就用一句英文概括)**
    > 中文标题 · [来源](https://…)
    >
    > 据报道,……(2–3 句大白话讲清发生了什么)。对你:……(这事对普通人意味着什么)
    >
    > ---
    > (下一条)
    ```
  - **「对你:」= 这事对老百姓、对普通人意味着什么**,每条都要有。用户原话:「对你是指对老百姓、对普通人有什么影响,因为有时候这些国家大事我看不懂」——所以这句的活是**帮她看懂**:用大白话把国家大事翻译到普通人够得着的层面(钱包:物价、油价、房贷、存款利息、汇率、工作机会;生活:出行、出境、买到的东西;再远一点:世界会不会更乱)。离普通人确实远就直说「离普通人还远」,再说一句它可能经由什么传导过来;看不懂的背景先在「据报道」那段补一句来龙去脉。**不往她的工作上接,也不往车上扯**——汽车那一条也是讲对买车、开车的人有什么影响;`check_news_brief.py` 拦「对你」提到车的超过 1 条。推测的影响标 (推论)
  - **说清不确定性**:说法只有一方来源就写「据 X 说」「未获独立证实」;只看到标题就直说「我只看了标题」。正文段不以粗体开头(CSS 会把它当标题行)
  - 写完跑 `python3 Meta/scripts/check_news_brief.py`(位置、每条有来源链接、每条有「对你:」且扯到车的不超过 1 条、链接都在候选清单里、和上一期没撞链接),不通过就改;后置体检会再跑一次

- **🎴 今日抽卡**:从 `Notes/` 挑"最久没被抽过"的——**优先看各篇 frontmatter 的 `last-surfaced:`,没有这个字段的排最前**(翻 git log 只作兜底,贵)。抽中之后**必须给被抽中的每篇写上 `last-surfaced: 今天日期`**(有就覆盖),这一行让下次挑选和 `gc_report.py` 都变成免费的。出 1-3 道回忆提示。**格式只有标题+问题列表,不加任何引导语**——不要加"先别点开"、"想不起来再点进去"之类的提示句,直接呈现问题本身。
- **🌱 今日延伸**:挑一个概念页(优先最近被链到的、或延伸区还空着的),补一条外部知识,标 [事实]/[推论]/[观点]、注明未联网核查;同步写进该概念页延伸区。**引用某篇笔记的录入时间时用实际日期。
- **📖 今日一读**:每天**一篇**,只读不写——用户这一栏不需要留任何回答。前身是每天两道提问,停掉的原因是台账里的实测:最后三周 21 道挂着「未答」,占当期一多半;而没答的题第二天又不许原样再问,于是每天真正的产出变成"再找两个还没问过的角度",不是内容。**读物换成六个体裁轮着来**,每个体裁的产物长得不一样,重复的压力自然比"每天两道自省题"低得多:

  | 体裁 | 干什么 | 选材入口 | 收工时必须留下的东西 |
  | --- | --- | --- | --- |
  | `对撞` | 库里两条判断打架:摆出来、说清分歧在哪、给立场 | `Meta/index.md` + `search_memory.py` | 无(纯读物) |
  | `核查` | 队列里取一条引用状主张,当场联网核实 | `python3 Meta/scripts/claim_audit.py --queue`(核心层排前面) | 回写宿主笔记的标注:`已联网核查`+链接 / 更正 / 查无此说 |
  | `复核` | 到期的 `checkable` 笔记,重验主结论 | `python3 Meta/scripts/review_due.py` | 该篇 `## 复核记录` 追一行(格式见 `Meta/GC.md`) |
  | `串线` | 把散在三四篇里的同一条线索连起来讲一遍 | `Meta/index.md` | 够格就按 `Meta/CONCEPTS.md` 提名概念(只提名) |
  | `反例` | 给库里一条判断找外部最强的反驳或边界条件 | 任一笔记 + 库外知识 | 反驳站得住就追进该篇/概念页的相应区块 |
  | `旧信` | 回放一段 `Diary/` 或用户自己写下的原话,配一句现在读出来的东西 | `Diary/<年>/` 近几个月、或某篇的「原话」段 | 无(纯读物) |

  **选材前必须先跑 `python3 Meta/scripts/reading_log.py`**——每天的生成是一次没有记忆的冷启动,不查台账就必然滑向最好写的那一个体裁(旧提问那套就是这么绕回同几个概念的:同一篇笔记 7 天内被问了两次,措辞都不一样所以自己看不出来)。它打印近 90 天出过什么、每个体裁的冷热、**今天建议的体裁**(可用的里面最久没出过的)、禁用素材。四条硬规则:
  - **同一体裁 3 天内不重出、14 天内最多 3 次**。建议的那个体裁今天没素材(claim 队列空了、没有到期复核)就换下一个,**别为了凑体裁硬写一篇**——`--check` 只管冷却和配额,不管是不是建议的那一个,所以永远有合法的下一步
  - **同一篇笔记/概念页 14 天内不许再当素材**;一篇用了几个素材,每个都各占各的冷却期。纯外部素材写 `外部`、日记出的写 `Diary`,这两类不占冷却期
  - **主旨和台账里任何一条撞车就作废**,换个体裁讲同一件事也算。`--check` 的相似度阈值是**下限不是上限**——机器拦得住的是字面接近的,读着眼熟但字面不像的,得自己换掉(同体裁最近两篇它会打印出来,逐条读一遍)
  - **体裁是闭集,不许当天临时起一个新的**。旧提问台账的《轴表》允许当期加轴,结果加轴成了绕开查重最省事的路;要加体裁就同时改 `reading_log.py` 和这份文件
  - 出完稿往 `Meta/阅读台账.md` 追加一行(格式 `日期 | 体裁 | 素材 | 主旨`,见该文件),然后跑 `python3 Meta/scripts/reading_log.py --check`,**不通过就换一篇**;别把不通过的结果推上去——CI 体检会再跑一次,拦不住的话当天日更整个失败、白跑一趟

  **版面**:单张顶层 callout,排在 🌱 延伸之后、📔 日记之前,整行通宽。
  1. 标题固定 `> [!read] 📖 今日一读 · <体裁> · <一句话标题>`——**`· 体裁 ·` 这一段不能省**,`--check` 拿它和台账对账(两边对不上说明生成到一半换过题,页面和台账会各说各话)
  2. 正文 2–5 段。引用素材原文、并列两条打架的判断、贴日记原段,都用嵌套 `[!note]` 子 callout(`> >` 包一层),标题写清这段是谁说的(如 `📄 库里这么写的`、`📮 2026-07 的日记`)
  3. **最后一段以 `**落点：**` 开头**,是全卡视觉最重的部分(CSS 给了左边框 + 加粗),必须落在真正的判断上,不要和稀泥、不要都说有道理
  4. **不留回答区**。这一栏只读不写,用户唯一动笔的地方是页面最后的 📔 日记井
  5. **提到的每篇笔记/概念页都挂双链**(`[[路径|显示名]]`),读到一半想翻原文时点得进去
  6. **措辞用简单直白的口语**:不堆概念术语、不写长复杂句——得先在脑子里查一遍这些词什么意思才读得懂,这已经构成理解障碍而不是引出思考;需要的背景直接用大白话嵌进正文里讲清楚,不要求读的人自己代入行话或去翻概念页
  7. **引用库内内容连来源一起报**(按 CLAUDE.md 那条):嵌进来的引文标清它那篇的 `source:` 和核没核实过——这个库六成以上的笔记来源就是和 AI 的对话,不标等于把一条模型回忆洗成有出处的事实

  ⚠️ **下面几条和"要有立场"同等级,不是可选加分项**。要防的是落点全落在"这印证了你库里已经有的某条模式"上,整段论据一条都出不了本库——那正是 CLAUDE.md 反信息茧房第 3 条的不合格判据。
  - **`对撞`/`核查`/`复核`/`反例` 四个体裁,卡里必须有一块本库里查不到的东西**:成熟外部知识(心理学/社科/医学里具体的研究、机制、反例、量级数字),或者对"打架的两边共同默认的那个前提"的拆解。`--check` 只查得到 [事实]/[推论]/[观点] 标记在不在,查不了标记后面那句是不是真的库外知识——机器信号是下限,不是通过就算合格
  - **禁止把「这接上了你早就报过的模式 X」当成落点**。把一个行为归到已有的画像标签上是换标签,不是解释;而且这是记忆库最容易自我强化的方向——库里存着的模式,重新认出来一次就显得很有洞察,实际信息量为零。可以提这个模式,但必须再往后走一步:外部知识对这类行为怎么说、有没有更好的解释、这个标签在哪里是错的
  - **`对撞` 优先去查两边共享的那个隐含前提**。最值钱的时候不是判谁对,是发现两边默认了同一个错的动作或定义(比如两边都默认"关系往深走 = 打听对方私事",而社会渗透理论说机制是自我披露的相互升级,"礼貌"挡住的是一个本来就不该做的动作——这一步把整场"哪条原因才是真的"之争直接架空)
  - 外部知识照 CLAUDE.md 标 [事实]/[推论];**执行器有联网工具时必须当场核查作者、年份、期刊,不要凭印象写引用**,核查过就在标注里写明"已联网核查"+链接
  - **自检**:写完把论据逐条过一遍,若全部都能在本库 grep 到,这篇不合格,重写
  - **回写宿主笔记算写入**(核查改标注、复核追复核记录、反例追进正文),按 CLAUDE.md 的规矩在 commit message 里写明改了哪几篇;改了 `Notes/`/`Concepts/` 就重建索引

- **📔 今日日记**:固定排在页面**最后**,在 📖 今日一读之后。结构就是一个顶层 `[!write] 📔 今日日记`(标题里的 📔 不能丢——`Home.md` 挂日记按钮的 dataviewjs 靠它认这个井,认不到就静默不挂、不报错),内容留两行空的引用行给用户手写,**markdown 里不预设任何文字、不出题**——它是空白页,不是问答。**井里不要加提示语**——写进井里的任何文字都会被下面归档流程第 2 条当成用户手写的日记原文抄进 `Diary/`,每天抄一遍。归档流程:
