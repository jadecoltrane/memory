# CONCEPTS — 概念层规则

只在**实际写 note、建概念页、或维护概念页**时才需要读这份文件;平时聊天不用加载。

`Concepts/` 每页一个原子概念,让图谱主要靠概念连接串起来(而不是只靠文档互相引用)。页面结构四段:一句话定义(用用户自己的话)、出现在(链回笔记)、相关概念(概念互链)、延伸+开放问题(AI 补充)。

## 双链规则(hub-and-spoke,已由 lint 强制)

笔记正文双链**默认优先**指向概念页(`[[Concepts/某概念]]`),概念页是枢纽、笔记是辐条;但**笔记之间也允许直接互链**——出处/背景引用、强绑定的一对、或走概念反而绕远时,直连更贴合就直连。判断标准是哪种最贴合内容,不是一刀切禁止(2026-08-09 用户放开)。

**硬上限:单篇 note→note 双链 ≤ 2 条**,超了 `lint_memory.py` 报警告。两种合规写法:

- **确实是同一论证的上下篇** → 在含该链接的**那一行**里写上「上下篇」「上篇」或「下篇」,该行豁免不计数。必须是真的连续(同一场对话的相邻轮次、A 篇被 B 篇修正/推翻、明确的续篇),不是"这两篇有点像"
- **只是主题呼应** → 双链改指两篇共有的那个概念页,另一篇写成**纯文本路径**(`Notes/xxx/yyy`,不加方括号)。读者照样找得到,图谱边却走枢纽,不会长成网

2026-08-02 立此规:那天一天写出 100 条 note→note 链、22 篇超标,图谱从星形塌成了网。清理后全库 0 超标。

**同义词用 aliases 收编,不开新节点**:概念页 frontmatter 加 `aliases: [同义表述1, ...]`;写双链前先扫一眼 index 的概念列表和已有 aliases。GC 时发现近义幽灵概念,合并进实体页 aliases 并改写旧链接。

## 懒加载(控制 token 成本)

1. **录入时只做最小动作**:概念出现处写 `[[Concepts/xxx]]`,概念页不存在也照写(图谱 `hideUnresolved: false`,幽灵节点零成本)
2. **第二次命中才建页**:被第二篇笔记链到时才创建实体页,只写「定义+出现在」,延伸留空
3. **延伸和开放问题只在两个时机写**:用户主动要求展开时;每周 GC 挑 1-2 个本周新命中的概念补。**绝不在录入时顺手写延伸**

frontmatter 用 `type: concept`;延伸区每条标注 [事实]/[推论]/[观点],凭训练知识写的注明"未联网核查",禁止编造引用链接。

## 晋升机制(概念页不会长成论文)

「延伸」区上限 **6 条**,超了 lint 报警告。这不是让你删内容,是提示该做一次**晋升**——概念页越用越厚是必然的,但厚的地方应该是**定义**,不是流水账式的延伸列表:

1. **已成定论的 → 折进定义段**:那些反复被用到、不再有争议、已经变成"这个概念本来就该这么理解"的条目,压缩成一两句话吸收进页首定义(标一句「已晋升(日期,由延伸区折入)」),然后从延伸里删掉。定义因此逐渐变准变厚——这就是概念在长大
2. **存疑或只用过一次的 → 移进「已探讨」**,附一行结论,不删
3. **仍然活跃、还在被新笔记引用的 → 留在延伸**

结果:延伸区永远只有"当前在用的那几条",不是编年史。概念页的长度因此有上界,而它承载的判断没有上界。

## 开放问题的生命周期(概念页永远不封口)

- **问题不因回答而消失**:用户在会话里回答了某个开放问题后,将该问题移入 `## 已探讨` 区块,附一句结论摘要(一行,不展开)——保留推进痕迹,不删除
- **答案可以繁殖新问题**:如果用户的回答带出了新的未解角度,直接在 `## 开放问题` 里追加新问题;问题区只增不减(除非用户主动删)
- **新笔记链到概念 → 检查是否带来新张力**:每次新 note 链到某概念时,顺手看这篇 note 有没有引入新角度或矛盾;有则追加到该概念的开放问题里(不只是放到工作台)
- **GC 时也扫**:本周有新入链的概念,检查开放问题是否需要更新
