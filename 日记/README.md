# 日记/ — 发生过的事

和 `notes/`、`作品/` 平级的第三种东西。三者的分工:

| | notes/ | 作品/ | 日记/ |
|---|---|---|---|
| 装什么 | 想通的东西 | 做出来的东西 | 发生过的事 |
| `tier:` | 要 | 不要 | 不要 |
| 进图谱 | 进 | 不进 | 不进 |
| 被 GC 整理 | 会 | 不会 | **绝对不能** |
| 进索引 | 进 | 不进 | **只进最近一个月** |

## 最后两行是重点

**GC 永远不许碰日记**——不去重、不合并、不建议淡出、不归档。「这个月第三次因为同一件事烦」在 `notes/` 里是冗余,在日记里恰恰是**信号**。任何"这两篇内容重复了"的判断,对日记都不成立。

**但日记进索引,而且我(AI)会读。** 2026-08-16 用户明确要求:让 AI 看得见,可以据此了解和分析用户。

**索引里只列最近一个月**(同日定的,防止一年之后开工时先吞 12 个月的日记)。更早的月份索引里只留一行说明它们存在——**需要往回看时自己去 `日记/<年>/` 翻**,别因为索引里没有就当它不存在。所以:

- 日记是 `profile/` 的合法输入源。从日记里归纳出的画像,照 `CLAUDE.md` 的规矩来——客观事实说一次就记,软特质要么用户明确表达过、要么不同场合重复 ≥2 次才写,每条附依据和日期
- **写进 profile 照样必须告知**(「🧠 已写入记忆:...」),不能因为素材来自日记就默默写
- 日记本身**不因为被读过就变成笔记**。看到值得沉淀的东西,按 `meta/RESOLVER.md` 走正常流程,原文留在日记里不动

## 组织方式

**一个月一个文件**:`日记/2026/2026-08.md`,里面每天一个 `## 2026-08-16` 标题。一年 12 个文件,手机上好翻,diff 也干净。

不需要 frontmatter,不需要双链。想引用某篇笔记就写纯文本路径。

## 怎么写进来

两条路,都行:

1. **工作台**:每日回路里有 `[!write] 📔 今日日记` 输入井,在那儿写,第二天日更自动归档进对应月份文件(规范见 `meta/WORKBENCH.md`)
2. **直接写**:在 Obsidian 里打开当月文件,自己加一个 `## 日期` 段

## 不受 12 篇上限约束

`lint_memory.py` 的文件夹上限只管 `notes/`,日记天然在管辖之外。按年份分文件夹就够了。
