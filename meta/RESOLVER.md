# RESOLVER — 新内容该放哪

按顺序判断,命中第一条就停,不用继续往下看:

1. **用户自己在 Obsidian 手写、推送到了 GitHub,没有触发词** → `notes/`(GC 或用户主动触发「帮我梳理一下 notes」时补齐分类、frontmatter、双链)
2. **用户说了**「记下来」「存一下」「收藏这条」「写进记忆库」「remember this」等触发词 → **先判断内容性质,不是无脑塞进 notes/**:
   - 文章、知识点、用户自己的想法/创作/经历 → `notes/`(提炼后写入,完整流程见下方「写 notes 的执行流程」)
   - 关于用户本人的稳定信息或偏好 → `profile/` 对应主题页(不进 notes/)
   - 对 AI 未来工作方式的约束或决定 → 直接写进 `CLAUDE.md` 对应规则(不单开记忆文件)
   - 一条内容同时沾两类(比如"以后笔记都用 X 格式"既是知识又是约束)→ 知识部分写 `notes/`,约束部分写进 `CLAUDE.md` 规则
3. **观察到用户本人的稳定特质**(行为准则、偏好、兴趣——用户明确表达过,或重复出现 ≥2 次)→ 更新 `profile/` 对应主题页,附依据和日期(不需要触发词,主动写,写完告知;见 CLAUDE.md「用户画像」一节)
4. 都不是 → **什么都不写**

**不要写**:代码里 grep 就能查到的事实、一次性任务细节、没有复用价值的流水账、记忆库自身的运营流水——记忆库只记用户(profile)和用户的知识(notes + concepts),不记 AI 自己的操作流水或抽象判断。对 AI 未来工作方式的硬约束直接写进 `CLAUDE.md` 规则,不单开记忆文件。

**只有写 notes/ 时**才按 `meta/CONCEPTS.md` 的规则在正文概念出现处挂 `[[concepts/xxx]]` 链接(概念页不存在也照写,幽灵节点零成本);笔记之间不直接互链。`concepts/` 不是录入目的地——概念页只在被第二篇笔记命中时才建。**profile/ 不挂概念链、不做双链进图谱**,引用其他记忆用纯文本路径;图谱只属于用户的知识(notes + concepts)。

写完之后:重跑 `python3 meta/scripts/build_memory_index.py` 更新索引;最后按 CLAUDE.md「写入必须告知」的格式告诉用户。

## 写 notes 的执行流程

上面判断出「该写 notes/」之后才走这一节:

1. 提炼成一条笔记(不是全文粘贴)
2. frontmatter 用 `type: note`,加一行 `source:`、一行 `tier:`(三选一,见下);可自由建子文件夹分类,索引脚本递归收录。**单个子文件夹超过 12 篇就该拆**(lint 会警告)
3. 写入本仓库、重跑索引、提交推送到 main。**"记下来"永远指写进这个 git 仓库**,不是会话内的短期记忆或任何 AI 产品自带的记忆功能
4. 当前会话没有本仓库时先获取(远程会话用 add_repo 添加 jadecoltrane/memory;本地会话直接操作用户磁盘上的 clone),实在无法访问时把写好的内容整段输出给用户手动保存

### 分层:tier(决定这条以后能不能淡出)

索引按这三层分组展示,🧠 在最上、📖 垫底,想只看要紧的就从上往下读、把最后一段折叠掉。

- **`tier: 核心`** 🧠 —— 用户自己的判断、立场、经历、反复回来的问题。**永不自动降级、永不建议删除**,过时了也是"这个人当时怎么想"的记录
- **`tier: 方法`** 🔧 —— 可执行的做法、清单、操作流程。会被更好的做法替代,替代时按 GC 的去重合并处理
- **`tier: 参考`** 📖 —— 外部知识、事实、别人的理论、一次性查阅材料。**这一层允许淡出**——过时了换一份就行,不需要用户下"删除"的决心;GC 里唯一可以主动列进摘要建议清理的就是它

拿不准写哪层时看一个问题:**这条如果三年后被证伪,损失的是"一个事实"还是"我的一段想法"?** 前者是参考,后者是核心。

### 先判断是否"可查证"

- **事实性/可查证**(数据、健康、历史、科学结论、他人转述的客观陈述等):走 verified + 复核流程
- **主观性/不可查证**(个人想法、感受、散文、创作、经历叙述、审美偏好):frontmatter 加 `checkable: false`,**不设 verified 字段,永远不进复核队列**——这类内容没有"对不对",原样留存即可

**verified 标记**(仅 `checkable` 内容需要):内容来自用户自己亲历/验证过的判断 → `verified: true`;转述自其他 AI、网络、他人、未经交叉核实 → `verified: false`。拿不准时默认 `false`。

### 图片(截图等)

用户发图片并说「记下来」时:

1. 原图保存到 `notes/assets/YYYY-MM-DD-简短描述.png`(或原格式,不要转码压缩)
2. 对应 note 里用 `![说明](assets/文件名)` 嵌入原图,**并且必须额外写一段文字提炼**——图片本身无法被索引和 grep,未来 AI 靠这段文字才知道这条记忆在讲什么
3. 单张截图正常几百 KB 到几 MB,GitHub 单文件上限 100MB,无需顾虑;但不要把长视频或高清大图仓库当网盘用
