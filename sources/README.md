# sources/ — 导出原文与对照表

**不进索引、不进图谱、不参与 GC 整理、不被 lint 检查**,所以躺着不被读就是 0 token。平时不用打开,只在两种时候用:怀疑某次记录漏了东西、要给新导出建对照表。

## 存两样:对照表 + 原文

- **对照表** `sources/YYYY-MM-DD-简述.md` —— 一轮一行,记去向。26 轮 ≈ 30 行,比 5682 行原文便宜两个数量级,把"我记了什么、丢了什么"从**可重查**变成**可查询**。
- **原文** `sources/raw/同名文件` —— 对照表说"第 19 轮漏了",没有原文这句话就永远无法复核、也捞不回来。

> **只存哈希不行**:哈希只回答"文件变没变过",回答不了"我从里面漏了什么"。

来历:2026-07-31 那次从一份 26 轮的导出里漏掉整整四块,**能被发现纯属侥幸**(用户手机里恰好留着截图)。原文默认不入库的旧规则也在同日被推翻——「我可能会把原文删了」,而上传目录会话一结束就清空,**防线依赖一个几小时后消失的副本等于没有防线**。

## 原文一律原样入库:不脱敏、不删行、不做隐私筛

2026-08-02 定:**脱敏过的"原文"就不是原文了**——对照表说"第 19 轮漏了",拿一份被删过行的文件去复核毫无意义。原来那条「有敏感内容就删掉那几行再入库」自相矛盾,已废除。

代价是清楚的:原文进了 git 历史,再想拿掉就得重写历史(这个库 2026-07-11 干过一次,82 个提交,而且 GitHub 缓存的旧提交仍可通过旧 SHA 访问)。所以控制点不在文件层,在仓库层:

> ⚠️ **这个仓库必须始终是 private。** 这是原文入库的唯一前提,也是唯一需要守的那条线。

~~`.github/workflows/lint.yml` 每次推送都会查一次可见性~~ —— **2026-08-16 按用户要求删掉了这个检查**。现在仓库变成 public 不会有任何自动告警,守这条线的只有人自己。改仓库设置前先想一下这一段。

一份 26 轮导出约 120 KB,存一百份也才 12 MB。**别为省体积牺牲可追溯性。**

## 读原文:先列目录,再切片,永远不要整份 Read

存是 0 token,**读才花钱**——两份导出约 9.3 万字,整份读进上下文就是几万 token。用 `meta/scripts/source_slice.py`:

```
source_slice.py <文件>            # 列目录:每轮一行(时间 + 第一句)
source_slice.py <文件> -g 关键词   # 搜索:只回命中的轮次号,不回正文
source_slice.py <文件> 19         # 切片:只打印第 19 轮(19-21 取区间)
```

实测定位 + 取一轮 ≈ 整份读的 **8%**。

## 对照表格式

```yaml
type: source
来源: ChatGPT / Gemini / Claude ...
对话日期: 2026-07-30 ~ 2026-07-31
轮次: 26
sha256: <原文哈希>
原文入库: true(`sources/raw/同名文件`)
审计日期: YYYY-MM-DD
```

正文一张表,一轮一行 `时间 | 一句话主题 | 去向`,去向三选一:

- ✅ 进了哪篇笔记(写路径)
- ⚠️ 半记(注明哪部分没记)
- ❌ 没记(注明为什么判断不用记,或"漏了")
